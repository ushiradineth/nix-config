# Why

Anchor the question in the current source, symbol and relevant behavior. Inspect focused git
history, blame, tests and linked PRs or issues. Follow the available record that could explain the
decision; do not search every connected service merely because a tool exists.

Use authoritative primary evidence. Query relevant documents, issue discussion or observability when
they can distinguish hypotheses and are available within the task's access. A large independent
investigation may use read-only workers; a narrow question stays inline.

Distinguish what the record says, what the code implies and what remains unknown. Preserve
uncertainty when summarizing another investigator. A missing record is a result, not permission to
invent intent. Avoid treating the newest commit as the whole history.

Return the rationale, competing explanations, source links and gaps. If a change is also requested,
turn evidenced constraints into what to preserve, change or avoid, then return to the active
playbook. A why-only request stops at the explanation.

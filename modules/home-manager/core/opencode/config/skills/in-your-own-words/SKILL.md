# In your own words

Restate what the user wants and the problem they are solving in plain language. Include the smallest
checkable outcome and material constraints. Separate an inferred assumption from something the user
actually said. Do not prescribe an implementation before understanding the problem.

Do not wait for confirmation unless a missing answer changes the result. If restatement is the whole
request, stop after it.

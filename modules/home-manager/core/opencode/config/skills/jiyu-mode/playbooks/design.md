# Design, prototype or plan

1. Read the current constraints and callers with `how`. Distinguish a product choice from an
   empirical question.
2. Use `architect` for new ownership, interfaces or state modeling. Answer uncertain behavior,
   performance or layout with the smallest disposable prototype and an observable comparison. Use
   `arena` when competing implementations would materially inform the decision.
3. If implementation is requested, continue in this session with the chosen shape. Stop for design
   approval only when the user requested that gate or a real authority boundary requires it.
4. If the requested deliverable is a plan, write the settled design, dependency order, verifiable
   units, validation commands and real stop conditions. Resolve observable unknowns before the plan;
   name unresolved product choices. Return the plan and stop before implementation.

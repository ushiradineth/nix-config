# Continuity

## Pick up

Read the user's latest objective, task-local plan/log, actual branch, dirty state and existing
evidence. Reuse completed work. Verify inherited claims only where their inputs changed or evidence
is missing. State the resume point and continue the relevant playbook.

## Catch up

Use `ketchup` for a read-only status. The latest user question steers the task; it does not cancel
it. Answer briefly and resume already-authorized work unless the user asked to pause.

## Pause

Pause only when requested or forced by a real runtime limit. Leave files coherent, stop only
task-owned processes, and record the goal, current state, decisions, evidence, blockers and next
step. Commit a checkpoint only if authorized. Context compaction alone is not a request to stop.

# Teach

Work out what the user needs to understand from the conversation. Use `how` for mechanics and `why`
when the motivation matters. Reuse available findings instead of launching both workflows again for
every explanation.

Start with a plain definition and the concrete problem it solves. Walk through the relevant user
action, data flow or state transition, then explain the tradeoff. Preserve evidence and uncertainty.
Do not turn an explanation into a list of function names.

Use a small diagram or example when it makes the mechanism clearer. Add complexity progressively
rather than drawing every subsystem at once. A simple point needs no visual or image generation.

Answer at the requested depth without quizzes, pacing commands or a forced lecture format. Stay
read-only unless implementation is separately requested.
